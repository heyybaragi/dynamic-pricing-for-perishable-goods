# Dynamic Pricing for Perishable Goods

A data science capstone project that builds an end-to-end dynamic pricing pipeline for perishable grocery inventory — combining demand forecasting, price elasticity estimation, spoilage prediction, and profit optimization into a single system with an interactive Streamlit dashboard.

---

## The problem

Perishable goods lose value as they approach expiry. Static pricing leaves money on the table — either through spoilage waste or missed revenue. This project builds a pipeline that recommends dynamic discounts based on days until expiry, predicted demand, and price elasticity, then simulates the profit impact against a baseline fixed-discount strategy.

---

## Data

This project uses two public datasets available on Kaggle:

- **[Dunnhumby — The Complete Journey](https://www.kaggle.com/datasets/frtgnn/dunnhumby-the-complete-journey)** — household-level transaction data from a US grocery retailer including purchases, coupons, and campaigns
- **[Perishable Goods Management Dataset](https://www.kaggle.com/datasets/suraj520/perishable-goods-management-dataset)** — synthetic perishable inventory data with expiry dates, spoilage records, and pricing

Download both datasets and place them in `Datasets/` before running the pipeline.

---

## What the pipeline does

| Stage | Module | Description |
|---|---|---|
| 1 | `demand_forecast.py` | Demand forecasting using LightGBM, Prophet, and Holt-Winters |
| 2 | `elasticity.py` | Price elasticity estimation using Dunnhumby out-of-sample data |
| 3 | `spoilage.py` | Spoilage risk classification comparing LR, RF, XGBoost, LightGBM |
| 4 | `optimizer.py` + `simulation.py` | Batch discount optimization and KPI simulation |
| 5 | `sensitivity.py` | Elasticity sensitivity analysis and stability checks |

## Running locally

**1. Install dependencies**

```bash
pip install -r requirements.txt
```

If Prophet fails to install via pip:

```bash
conda install -c conda-forge prophet -y
pip install -r requirements.txt
```

**2. Run the pipeline**

```bash
cd code
python run_pipeline.py --skip-prophet
```

Drop `--skip-prophet` for a full run including Prophet in the model comparison (adds ~5 minutes).

**3. Generate dashboard inputs**

```bash
python save_whatif_files.py
```

**4. Run the dashboard**

```bash
streamlit run "dashboard new.py"
```

Opens at http://localhost:8501.

## Key results

- Dynamic pricing outperforms fixed discounting on revenue and profit across most categories
- Ready-to-Eat stays negative under dynamic pricing due to structurally thin margins and high spoilage — flagged explicitly in the dashboard
- Spoilage model achieves strong classification performance; LightGBM selected as the final model
- Elasticity sensitivity analysis confirms the optimizer is robust to ±50% shifts in elasticity coefficients on non-near-expiry items

---

## Known limitations

- Elasticity OOS R² is negative for Produce and Meat because the test strips store and week fixed effects — the elasticity coefficient itself is stable, which is what the validation demonstrates
- Spoilage target is binary (units wasted > 0) rather than a magnitude prediction
- The ±50% elasticity sensitivity on the full sample shows near-identical profits because 42% of rows hit the near-expiry override — the non-near-expiry variant is the meaningful test
